zaystatic is **0.x software**. The on-disk content format is meant to stay stable; the public API may still change before 1.0. The full, detailed plan lives in `ROADMAP.md` in the repository; this page is the summary.

## Verified

- Automated tests cover the content engine, validation, the HTTP handler and its guards, session sealing, the GitHub store and the whole pull-request workflow against an in-process fake GitHub, the S3 signer (checked against AWS's published test vector), uploads, the Node adapter and the language logic.
- Drag and drop, saving, translation tabs, validation messages, uploads, the media library, blocks and the block builder were exercised by hand in a real browser, in local mode.

## Not yet verified against real services

- GitHub sign-in with a real OAuth App, and real GitHub writes.
- A real S3 or R2 bucket.
- A real pull-request round trip, and deploy previews.
- The draft interface with a draft present in a browser.

Treat these as unverified until you have tried them on your own setup, and please tell us what you find.

## Planned

**Editing experience**: a live preview of the rendered page, a rich-text mode for markdown, content-wide search, "used in" and broken-reference warnings, a conflict screen, and undo and redo.

**Block builder**: typing straight into previews, nested blocks and columns, keyboard shortcuts, phone and tablet preview widths, reusable blocks.

**Workflow and access**: roles and per-collection permissions, history and revert, scheduled publishing, GitLab, Bitbucket and Gitea, other sign-in providers.

**Developer experience**: generated TypeScript types and a typed reader, server-side custom validators, a schema migration helper, presigned uploads, image pipeline hooks, starter templates and a widget gallery.

**Quality**: browser-level tests for the panel, an accessibility audit, more panel languages.

## Known limitations

- The panel is React-only (the server is not).
- Uploads pass through your server, so platform body limits apply.
- GitHub only; one allow-list, no roles.
- No rendered preview; markdown is edited as raw text.
- Concurrent editing is last-writer-wins at the file level.
- The pull-request workflow needs GitHub mode.
